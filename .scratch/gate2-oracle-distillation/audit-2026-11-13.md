# Audit: why the ILP does not learn the oracle's gain (2026-11-13)

Read-only audit of the Gate 2 pipeline after the robust-label result (results-robust.md).

## Checked, no bug found

| part | check | result |
|---|---|---|
| oracle labels reach training | `train_rules --oracle-labels` reads `selected` of the oracle run | yes: training precision changes, and multi_criteria learns a different clause |
| imitation control | same states, teacher's labels (`teacher_labels.parquet`) | yes (tests in test_oracle_labels.py) |
| robust oracle | pick must beat the teacher in all 3 futures | yes (unit tests; smoke run shows a 3-of-3 rejection) |
| no plain/robust mixing | train_rules refuses | yes (test) |
| leakage | induction seeds only; eval refuses artifacts trained on its seeds | yes (seed_split guards) |
| matcher | oracle:T runs under T's matcher | yes (teachers.matching_for) |
| evaluation | robust artifacts used | yes (multi_criteria result differs from option A) |
| hard negatives | at an override the teacher's pair is a competitor of the oracle's pair | kept as a hard negative (sampler, closest competitors first) |
| offline/online predicates | one implementation (predicates.py), parity tests | yes |

## Design limits that explain the failure

1. **Signal dilution.** The 800-decision cap (sampler.py, M2 spec 5.5) keeps about half of
   the decisions. Decisive robust overrides that reach Popper: nearest_astar 37 of 84,
   multi_criteria 39 of 75, milp 53 of 80, among about 4,400 positive examples per teacher
   (about 1 %).
2. **Every example weighs the same.** `GroundAtomExample.weight` exists but is always 1;
   Popper's noisy (MDL) score counts errors, so a pick worth 10 s counts like a pick worth 0 s.
3. **The rule language cannot say "deviate here".** A clause marks pairs as acceptable; the
   matcher then orders them by fixed keys (clause rank, oldest order, static cost, finish).
   "Give the oldest order to a farther robot" is not expressible.
4. **The overrides look worse at decision time.** Robust decisive overrides (239): the
   oracle's pair has a longer route in 72 %, more route overlap in 64 %, lower energy margin
   in 66 %; conflict features split about 50/50.
5. **Search budget.** Every Popper run stopped at the 300 s timeout.

## Options (literature)

- **Teacher + learned exceptions** (default rules with exceptions, as in FOLD-R++,
  arXiv 2110.07843): learn only "when to deviate from the teacher", on the pivot decisions,
  with all decisive overrides as positives. Fixes 1 and 3; explanation reads "do what the
  teacher does, except when ...".
- **Cost-weighted examples** (VIPER's Q-DAgger weights states by how much a wrong action
  costs, arXiv 1805.08328): weight examples by the oracle's gain. Fixes 2.
- **Preference learning** (ILASP learns weak constraints from ordered pairs, arXiv
  1507.06566; FOLD-TR learns to rank, arXiv 2206.07295): learn "pair A is better than B".
  Fixes 3, but a new learner, too large for 20 Dec.

Before building any of them: a separability check. If a flexible classifier cannot tell
the oracle's pick from the teacher's on decision-time features (held-out runs), no rule
learner can, and limit 4 is the answer.

## Separability test (2026-11-13, read-only)

Scripts (scratchpad, not in the repo): `separability_extract.py` (cluster, project env) and
`separability_test.py`, `separability_test2.py` (local throwaway venv, scikit-learn 1.5.2).

Data: every alternative the robust oracle tried, rebuilt with `m6_candidates.select_candidates`
and `ORACLE_SEED` (0 mismatches over 4,995 decisions: count, teacher pair and pick all match).
14,422 alternatives; y = 1 for the 239 decisive robust improvements (1.66 %). Decision-time
features only: the pair's values and their difference to the teacher's pair (cost, finish,
battery, congestion, loads, advantage), the fleet load, fleet size and time.

| test | result |
|---|---|
| leave-one-seed-out AUC, all features (logistic / boosting) | 0.68 / 0.68 (shuffled-label control 0.46 / 0.44) |
| same, only pair-vs-teacher differences | **0.56 / 0.52** |
| train 104-107, test 108-110: precision of the top-k flagged (k = true count) | 0.05-0.09 (base 0.017) |
| at a decision that has a real improvement, right alternative ranked first | **39 % / 35 % (chance 35 %)** |
| strongest single features | time in run (AUC 0.32, i.e. early), robot SOC (0.68), pending orders (0.67) |

Reading: the features say partly **when** a real improvement is likely (early in the run,
many orders pending: an early change affects more of the remaining run), but not **which**
alternative it is: within a decision a flexible classifier is at chance, and flagged
deviations would be wrong more than 90 % of the time. "Teacher + exceptions" and cost
weighting cannot fix this; the limit is the information in the decision-time state, not
the learner. M6 conclusion: the robust gain (-4 to -6 %) exists but is not predictable
from decision-time features.
