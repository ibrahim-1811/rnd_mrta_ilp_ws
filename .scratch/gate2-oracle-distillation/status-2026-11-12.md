### Step 1. Train the six rule sets (cluster)

Three on oracle labels, three imitation controls on the same oracle states.
Vocabulary as in `plan.md:71`: `--extended --tier-b --battery --workload`.
`--teacher T` is required: the corpus check refuses runs driven by another strategy (`train_rules.py:142-144`).

```bash
mkdir -p runs/gate2/logs
for T in nearest_astar multi_criteria milp; do
  for L in oracle imitation; do
    if [ $L = oracle ]; then LAB="--oracle-labels"; else LAB="--label-teacher $T"; fi
    sbatch -p hpc1 --cpus-per-task=1 --mem=16G --time=06:00:00 --job-name=g2-$L-$T \
      --output=runs/gate2/logs/train_${L}_${T}_%j.out \
      --wrap="pixi run python -m ilp_learning.train_rules runs/gate2/o300/wholerun/$T/r*_s* \
        --out runs/gate2/rules/o300/${L}_$T --teacher $T \
        --extended --tier-b --battery --workload $LAB"
  done
done
```

- 6 jobs, 1 core each. Under the 5-tasks-per-array limit because they are plain jobs (`DECISIONS.md:2004-2005`).
- Runtime: Popper stops at 300 s. With knowledge-base building, expect about 10-30 min per job. This is an estimate, not measured for this corpus.
- Output: `runs/gate2/rules/o300/{oracle,imitation}_<teacher>/rule_artifact.json` plus `training_log.json`. The log prints clauses, program metrics and `timed out`.
- Check before going on: `grep -A3 "clauses" runs/gate2/logs/train_*.out`.
- IMPACT: this gives the first rule sets learned from decisions that beat the teacher.
  - Empty oracle program for a teacher = that teacher fails Gate 2 criterion 1 at once (`DECISIONS.md:2022`). An empty program falls back to FIFO (`DECISIONS.md:1732`).
  - All three empty = option A fails. Option B is then not run (`DECISIONS.md:2028-2029`). This is a reportable null result (`plan.md:84-87`).
  - Note from the measured data: the oracle overrides only about 9-10 of about 58 decisions per run. Oracle and imitation labels agree on roughly 84% of decisions, so the two arms may learn similar rules. That is the honest size of the label signal.

### Step 2. Closed-loop evaluation on validation seeds 116-120 (cluster)

One job per fleet size, the three teachers and the six students on the same workloads.

```bash
for N in 70 80 90 100; do
  R=""
  for T in nearest_astar multi_criteria milp; do
    R="$R oracle_$T=runs/gate2/rules/o300/oracle_$T/rule_artifact.json"
```

### Step 3. Gate 2 verdict (cluster login node or locally after copying `summary.csv` files; seconds)

```bash
pixi run python -m ilp_learning.gate2_verdict runs/gate2/eval/o300/r{70,80,90,100}/summary.csv \
  --pair ilp_oracle_nearest_astar=nearest_astar \
  --pair ilp_oracle_multi_criteria=multi_criteria \
  --pair ilp_oracle_milp=milp \
  --control ilp_oracle_nearest_astar=ilp_imitation_nearest_astar \
  --control ilp_oracle_multi_criteria=ilp_imitation_multi_criteria \
  --control ilp_oracle_milp=ilp_imitation_milp \
  --alternative less \
  --gate1 runs/gate1/o300/wholerun \
  --out runs/gate2/verdict_o300.json
```

- Learned arms appear as `ilp_<label>` in `summary.csv` (as `ilp_corrected_*` did in `runs/dev/corrected_eval/o300/r70/summary.csv`).
- Pass `--pair` only for the three oracle students. Holm is over the three teachers (`DECISIONS.md:2024`). Adding the imitation arms as pairs would make it six tests and break the frozen family.
- `--control` is a second Holm family, reported only (`gate2_verdict.py:18-20, 126-130`).
- `--gate1` adds the recovered share (`gate2_verdict.py:107-112`). The Gate 1 folder is on the cluster and local.
- Output: a table on screen and `runs/gate2/verdict_o300.json`.
- IMPACT:
  - **PASS for a teacher**: a symbolic rule set, learned only from decision-time predicates, beats that teacher closed loop. This is the first evidence that outcome-aware ILP outperforms its teacher (the research goal). It also lets CLAUDE.md's outcome-aware claim be made for that teacher.
  - **H1 contrast**: oracle-label student better than its imitation control. The gain comes from the labels, not from the new state distribution. Without it, a pass could mean "trained on better states", not "learned better choices".
  - **FAIL with rules firing**: the oracle's advantage is not expressible in the current predicates, or the student drifts off the oracle's states (`plan.md:84-90`). Next options would be DAgger-style relabelling or new predicates, each needing a decision.
  - **FAIL criterion 1** (empty, or fallback > 0.5): the rules do not decide the run. Option B stays closed.
