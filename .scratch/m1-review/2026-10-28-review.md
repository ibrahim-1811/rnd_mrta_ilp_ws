## Findings from source inspection

1. **Rollout verification can succeed without evidence.** `src/simulation_env/scripts/m1_probe.py:250` uses `all(...)` over clone checks. Empty checks pass; `--verify 0`, no suitable clone points, or no sampled decisions can therefore return success without demonstrating deterministic replay. Require an explicit verified status and at least one successful check before accepting rollout evidence; report unavailable alternatives and insufficient samples separately.

2. **The seed guard does not cover the resolved configuration.** `src/simulation_env/scripts/m1_probe.py:181` checks explicit argument seeds before `builder()` resolves a missing strategy seed from the configuration. A reserved seed supplied through the configuration bypasses that early check. An arbitrary orders file also carries no verified workload-seed provenance. Guard effective seeds before running; record workload origin separately from strategy RNG seed. Do not treat a safe strategy seed as proof that the workload is safe.

3. **Waiting attribution starts before the claimed decision instant.** `src/simulation_env/simulation_env/rollout.py:251` snapshots waiting at the clone point, while the module describes waiting accrued from the forced decision time. `measure()` subtracts that earlier snapshot. Record waiting at the forced decision or rename the metric to match its actual interval. Branches may also stop at different times; total waiting is not a common-horizon comparison as currently reported.

4. **Charging attribution is a proxy.** `src/simulation_env/simulation_env/outcome_signal.py:136` infers charging from an SOC increase between orders. A robot may charge and then spend enough energy before its next launch to hide that increase. The last order has no next observation but currently contributes a false value to the mean. Use observed charging events for ground-truth labels; meanwhile label this as a proxy and exclude censored final observations from its denominator.

5. **Length normalization is not statistical adjustment.** `src/simulation_env/simulation_env/outcome_signal.py:329` describes residual/estimate correlation as removing route-length effects. A ratio does not establish independent predictive information. Report these correlations as exploratory; use validation data and an explicit adjusted analysis before claiming added predictive value.

The findings above are source-level observations, not newly reproduced failing regression tests. Add targeted regression cases before fixing the corresponding behavior.
