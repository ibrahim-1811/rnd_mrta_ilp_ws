## Failures
1. test_experiment_integrity.py::test_overwrite_resume_and_force: `assert record["git"]["commit"]` -> ''. Cause: simulation_env/dataset.py git_state() shells out to `git rev-parse HEAD` and returns '' on failure; a `git archive` export has no repo. Passes (19/19 in file) with GIT_DIR pointing at the repo. Classification: dirty-tree/repo-state dependency (test requires running inside a git checkout) - NOT a code bug, but it WILL fail in any CI that does not check out .git (e.g. a tarball) and is worth hardening. A normal actions/checkout is fine.
2. Backend "Scientific interpreter is unavailable" (503): control_center/adapters/commands.py:51 hardcodes `REPO/.pixi/envs/default/bin/python` (REPO = Path(__file__).parents[5]) and fails at :60 if it is not a file; .pixi is gitignored. Reproduced: export without .pixi + PYTHONPATH -> 23 failed, 110 passed, 19 errors. Environment failure. With .pixi symlinked: 152 passed, with or without git metadata, so no dirty-tree file dependency. 
3. Backend collection error `No module named simulation_env` (6 files) when PYTHONPATH lacks the science src dirs: environment (the backend venv only editable-installs control_center). 
4. Backend run in a ROS-sourced shell: pytest aborts at startup (`launch_testing` pytest plugin from /opt/ros/jazzy -> No module named lark) because the ambient PYTHONPATH points to ROS. Environment. Use env -i / clean PYTHONPATH (or -p no:launch_testing...).
5. Backend env needs fastapi==0.119.1, uvicorn 0.38.0, websockets 15.0.1, httpx 0.28.1 (+pytest 8): present in ws backend/.venv (python symlinks to ws .pixi python, include-system-site-packages); NOT present in either pixi env. So the minimum is: backend .venv (pip install -e .[test]) + a pixi env at repo root. In a clean clone both are missing: the venv's python symlink points into ws/.pixi (absolute), and .pixi is untracked.
