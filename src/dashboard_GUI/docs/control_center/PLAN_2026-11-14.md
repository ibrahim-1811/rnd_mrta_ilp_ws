# Control Center plan, 14 November 2026

Status: proposal, awaiting the owner's approval. Timebox about 15-30 November, alongside
the R&D website; the M9 report follows.

## Goal

One local dashboard where the owner can:

1. see the whole fleet live (map, every robot, status, battery, live metrics);
2. run any of the 20 strategies, including the learned ILP arms, on any map;
3. choose any map that exists as an Excel file in `src/simulation_env/maps/`, or upload one;
4. launch Gazebo for any map and strategy, with live explanations;
5. replay any recorded run without Gazebo in a 2D player;
6. see every metric and graph, including both campaigns and their statistics.

The scientific boundary does not move: the dashboard only selects inputs and launches the
same CLI and ROS commands. It never routes, allocates, or changes a result.

## Starting point (evidence: AUDIT_2026-11-14.md, MERGE_2026-11-14.md)

- Merged into the research tree; frontend 27 tests, type check and build clean; backend
  151 passed, 23 fail or error, all from the observed-runner guard (`RUNNER_SHA256`).
- Five screens (Operations, Gazebo, Experiments, Run history, System), state-based
  navigation, no URL routes, no dark theme, 10 px type in places, no results or charts.
- W100 hard-coded in 12+ places; `/strategies` lists 9 ids; ILP only as a typed path in a
  single CLI run; the experiment matrix excludes ILP.
- Campaign results not discoverable: `/experiments` returns 413 (more than 10,000
  directories), `/runs` times out after 60 s on the 10,346 run folders.
- Live view off: the observed adapter is guarded by the hash of `run_workload.py`, which
  changed with `--map`, seed roles and congestion features.

## Increments

Each increment: a `phase-coder` subagent (Sonnet) implements it; a separate review subagent
(Sonnet) checks it against this plan and the repo standards; Claude verifies with tests and
screenshots at desktop and phone width, light and dark; the owner reviews and commits.

| # | Increment | Acceptance |
|---|---|---|
| C1 | **Foundations.** URL routes per screen; dark theme (tokens, `prefers-color-scheme` and a toggle); type scale with nothing under 12 px; contrast and visible focus; capability flags read from the backend, not hard-coded; open on an overview, not the latest cancelled job; run discovery indexed from `summary.csv` / `run.json` files instead of walking every folder | screens load in under 2 s with all 10,346 run folders present; contrast AA; existing tests green |
| C2 | **Results screen** (read-only). Both campaigns: rankings of all 20 arms, D against its comparators per setting with intervals and Holm significance, the frozen transfer test, Friedman tables, all 16 metrics as charts, explanation metrics. The backend reads `runs/campaign/{final,transfer}/{o*/r*/summary.csv,stats,explain}`; numbers reuse `campaign_stats` | every number equals the M8 report and the stats CSVs (tested) |
| C3 | **Maps.** Scenario registry built from `maps/*.xlsx`; each map gets a generated config, world and nav graph under the dashboard's data folder (the one W100 config stays untouched). Upload of an `.xlsx`: saved by hash, checked by `map_tool.py check`, then `check_map_topology.py` as a queued job; selectable only after both pass. Remove the W100 hard-coding | W100, H100 and an uploaded copy selectable; a broken upload is rejected with the checker's message |
| C4 | **All strategies.** The 20 arms by name; rule files from a registry (`runs/campaign/rules/*`, D's Gate 2 set), shown with their clauses; ILP allowed in single runs, experiments and Gazebo; Gazebo launch passes `explain:=N` and the dashboard shows the explanation stream | every arm launches on W100 and H100 in CLI mode; one ILP Gazebo launch verified |
| C5 | **Live fleet.** Re-review the observed adapter against today's runner (map, seed roles, ILP, congestion), extend the parity smoke to ILP and H100, and only then update the guard. Live map with every robot, status and battery, plus live metric charts | observed and CLI runs identical (decisions, outcomes, metrics) for at least nearest_astar and D on W100 and H100 |
| C6 | **Replay.** Replay any recorded run (dashboard or campaign) by deterministic re-execution of its order file, seed, strategy and rules in observed mode, checked against the recorded metrics before display; 2D player with timeline, speed, robot selection and, for ILP runs, the explanation of each pick | a campaign run of D replays with metrics equal to its `summary.csv` row |
| C7 | **Finish.** Full `verify`, README and OPERATIONS updated, screenshots for the website | all gates green |

C1 and C2 come first because they are read-only and give the most value for the least risk.
C5 is required before C6, because replay uses the observed path.

## Not in scope

Remote access, user accounts, deployment, map editing in the browser, a second planner or
allocator, any change to scientific code.
